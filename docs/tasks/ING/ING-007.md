## Detailed implementation steps

### Micro-task 1

Persist source file load receipt while provider history is available; compare listed files, loaded rows, schema and embedded tenant identity.

### Micro-task 2

Require all files and manifest match; handle zero-file success explicitly. Publish accepted batch record idempotently and reconcile ack after crash.

### Micro-task 3

Load files out of order, omit one, duplicate one and supply a foreign-tenant row; assert all incomplete/invalid attempts are invisible to staging.

### Micro-task 4 — Prove and checkpoint

Run the validation below, record expected versus observed results and environment versions, update operational documentation, then checkpoint the task index with the exact next action. Do not mark DONE while a required live gate is unexecuted.

## Data model

Operational batch_files stores receipts/count/checksum/status; central accepted_batch version is the only staging inclusion gate.

## API / interfaces

Receipt poller+event hint; accept(batch_id,fencing_token) emits durable central acceptance and ack.

## Security and tenant isolation

Extractors receive one account identity and prefix; sanitize before serialization; reject file/prefix/manifest identity mismatch. RAW and quarantine are not product-readable.

For this task, test a foreign tenant identifier and an invalid or revoked scope at every input boundary it introduces. Internal infrastructure tasks instead prove environment/principal isolation and absence of public access. Test artifacts use synthetic tenant A/B data only.

## Idempotency / retries

Immutable attempts plus stable logical window IDs, fenced leases, acceptance gates, deterministic keys and contiguous checkpoints provide idempotent business results over at-least-once transport.

## Failure scenarios

Load history expired; manifest late; count mismatch; false success from partial file; acceptance event duplicated.
