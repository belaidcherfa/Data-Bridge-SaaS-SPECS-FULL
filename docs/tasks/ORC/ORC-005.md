## Detailed implementation steps

### Micro-task 1

Build candidate manifest referencing changed and unchanged partitions; enforce completeness and required check results.

### Micro-task 2

### Micro-task 3

Run the validation below, record expected versus observed results and environment versions, update operational documentation, then checkpoint the task index with the exact next action. Do not mark DONE while a required live gate is unexecuted.

## Data model

Publication manifest maps dataset/partition→physical revision and includes coverage/metric/config versions.

## API / interfaces

validate_candidate→Snowflake pointer transaction→control ack→cache/outbox event.

## Security and tenant isolation

Run configuration is server-derived and typed. Run tags and partition names are not authorization. Worker identities cannot choose other customer roles; UI is private and logs sanitized.

For this task, test a foreign tenant identifier and an invalid or revoked scope at every input boundary it introduces. Internal infrastructure tasks instead prove environment/principal isolation and absence of public access. Test artifacts use synthetic tenant A/B data only.

## Idempotency / retries

Dagster retries/sensor keys are hints; PostgreSQL fenced leases and source/publication keys enforce durable idempotency. Each publication pointer advances once per accepted candidate.

## Failure scenarios

Check passes on wrong version; stale config; partial partition map; GC deletes referenced revision.
