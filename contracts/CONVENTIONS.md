# Contract conventions (v1)

Status: ACCEPTED 2026-09-28 · Owner: tech lead / architecture · Applies to every contract, schema, migration, API and event in this monorepo. Agents MUST follow these rules; a contract that violates them fails review. Changing a rule requires an ADR amendment ([ADR-017](../docs/architecture/adr/ADR-017-repository-and-contract-layout.md)).

## 1. Where contracts live

This repository is the product monorepo (ADR-017). Specifications stay under `docs/`; executable contracts live at the paths below and are consumed directly by code, tests and CI.

| Kind | Canonical path | Format | Validated by |
|---|---|---|---|
| Cross-cutting conventions and common types | `contracts/common/*.schema.json` | JSON Schema 2020-12 | `make contracts-check` (ajv + check-jsonschema) |
| HTTP API (UI, public API, internal ops API) | `contracts/openapi/openapi.yaml` (root) + `contracts/openapi/paths/<domain>.yaml` + `contracts/openapi/components/<domain>.yaml` | OpenAPI 3.1 | Spectral (`contracts/.spectral.yaml`), Redocly bundle, Schemathesis in CI |
| Problem (error) catalog | `contracts/errors/problems/<domain>.yaml` (one file per domain, merged by tooling) | YAML, one entry per `code` | schema `contracts/errors/problems.schema.json`; codes unique across files |
| Domain events (outbox) | `contracts/events/catalog/<domain>.yaml` + `contracts/events/schemas/<type>.v<N>.schema.json` | YAML + JSON Schema | event catalog test; types unique |
| State machines | `contracts/state-machines/<machine>.yaml` | YAML, format in §9 | state-machine linter + generated transition tests |
| Capabilities, roles, scope grammar | `contracts/authz/capabilities.yaml`, `contracts/authz/roles.yaml`, `contracts/authz/scope.schema.json` | YAML + JSON Schema | authz matrix test |
| PostgreSQL control-plane schema | `contracts/postgres/<schema>[.<part>].sql` (reference DDL; one owner per file) | PostgreSQL 16+ SQL | Alembic migrations must converge to it (schema-diff test) |
| Snowflake central objects | `infra/snowflake/migrations/<schema>/V<NNNN>__<desc>.sql` | Snowflake SQL, versioned migrations (INF-104) | migration runner dry-run + grant audit |
| Data contracts (sources, ledger, datasets, dbt meta, checks) | `data/contracts/**` | JSON Schema / YAML / Markdown as named in the backlog | contract tests |
| Semantic metrics | `packages/semantic_metrics/**` | YAML + JSON Schema | registry compiler tests |
| Telemetry | `packages/telemetry/**` | JSON Schema / YAML | log-schema test |
| Infrastructure catalogs | `infra/**` (`environments`, `services.yaml`, `iam/`, `observability/`) | JSON/YAML + JSON Schema | `make infra-validate` |
| Owner-supplied environment configuration | `config/environments/<env>.yaml` (template `*.example.yaml`) | YAML validated by `config/environments/environment.schema.json` | `make config-validate` |
| Prose specifications that are contracts (policies, formula sheets) | `docs/**` at the path named in the backlog | Markdown with front matter | link + front-matter check |

Every contract file starts with a header (YAML/SQL comment or JSON `$comment`/`x-bridge` block) carrying: `contract`, `version`, `status` (`DRAFT` → `ACCEPTED` → `DEPRECATED`), `owner_task` (e.g. `FIN-001`), `decisions` (e.g. `D-12`), `last_changed`. An agent may create a `DRAFT`; only a reviewed PR sets `ACCEPTED`.

## 2. Naming

| Element | Rule | Example |
|---|---|---|
| JSON fields, query params, YAML keys | `snake_case` | `tenant_id`, `usage_date` |
| URL path segments | `kebab-case`, plural nouns, versioned prefix `/v1` | `/v1/billing-references/{reference_id}` |
| OpenAPI component schemas | `PascalCase` | `ChargeRow`, `Problem` |
| Enum values | `UPPER_SNAKE_CASE` | `PROVISIONAL`, `MONTH_STABLE` |
| PostgreSQL | schemas and tables `snake_case`, singular table nouns, no quoting | `connection.connection`, `sync.batch_attempt` |
| Snowflake | database `BRIDGE` (plus `BRIDGE_INTERNAL_COST`, `BRIDGE_CI`, `BRIDGE_DEV_SANDBOX`, `SIM` per INF); schemas and objects written UPPER in docs, lowercase unquoted in SQL; never quoted identifiers | `bridge.ledger.fct_charge` |
| dbt models | `stg_`, `int_`, `fct_`, `dim_`, `bridge_`, `mart_`, `srv_` prefixes; one model per file | `fct_charge`, `srv_spend_daily` |
| Event types | `bridge.<domain>.<entity>.<past_tense_verb>` + schema version suffix `v<N>` | `bridge.sync.batch.accepted` v1 |
| Problem codes | `<DOMAIN>_<CONDITION>` UPPER_SNAKE | `SYNC_LEASE_FENCED`, `AUTHZ_SCOPE_DENIED` |
| Capabilities | `<resource>.<action>` lower dot | `period.close`, `rule.publish` |
| Metrics (telemetry) | `bridge_<component>_<name>_<unit>` Prometheus style | `bridge_ingest_batch_accept_seconds` |
| Metric IDs (semantic) | `snake_case`, versioned by registry | `spend`, `attributed_cost` |

## 3. Identifiers

- Internal IDs are **UUIDv7** (time-ordered), generated by the application (`uuid6`/`uuid_utils` in Python, `uuidv7` npm package in the web app when a client-side draft ID is needed). PostgreSQL type `uuid`; Snowflake `VARCHAR(36)` lowercase canonical form.
- Every tenant-owned row carries `tenant_id uuid NOT NULL`; composite uniqueness and foreign keys include `tenant_id` (SEC RLS standard).
- External identifiers are kept verbatim as strings with their source: Snowflake `account_locator`, `region`, `organization_name`, `query_id`, `warehouse_id` (numbers stored as `NUMBER(38,0)` in Snowflake, `text` in PostgreSQL when used as keys).
- Deterministic IDs (for idempotency) use UUIDv5 over a namespace per contract with the canonical key tuple joined by `\u001f`: e.g. `logical_delivery_id = uuid5(NS_DELIVERY, event_id␟destination_id)`. Each namespace UUID is declared once in `contracts/common/namespaces.yaml`.
- Public/support references shown to humans may use a short prefix + Crockford base32 of the UUID tail (`tnt_7K2Q…`); they are display aliases, never keys.

## 4. Time

- All instants are UTC. JSON: RFC 3339 with `Z` and millisecond precision (`2026-09-01T00:00:00.000Z`). PostgreSQL: `timestamptz`. Snowflake: `TIMESTAMP_NTZ(9)` holding UTC, with every Bridge session forced to `TIMEZONE='UTC'` (connection parameter + user default); Account Usage `TIMESTAMP_LTZ` values are converted to UTC at extraction.
- Calendar dates are UTC dates (`DATE`, JSON `YYYY-MM-DD`). Financial periods are UTC months unless a tenant fiscal calendar (GOV-104, R2) is configured.
- Intervals are half-open `[start, end)` and named `<x>_start` / `<x>_end` (or `period.start` / `period.end` in JSON).
- Durations: integer milliseconds in APIs (`*_ms`), seconds in configuration (`*_seconds`), never floating hours.
- IANA time-zone names only for display preferences and report schedules (RPT-004).

## 5. Money, quantities and precision

- Money in JSON is an object `{"amount": "<decimal string>", "currency": "USD"}` validated by `contracts/common/money.schema.json`. `amount` matches `^-?(0|[1-9][0-9]{0,25})(\.[0-9]{1,12})?$`; signs are legal; `currency` is ISO 4217 uppercase. Never a JSON number, never a float anywhere in Python, TypeScript arithmetic or Parquet.
- Internal precision: Snowflake `NUMBER(38,12)`; Python `decimal.Decimal` with the context from `packages/bridge_money` (precision 38, `ROUND_HALF_EVEN` only where a contract says so); rounding to currency minor units happens only at statement/export boundaries (FIN-106) using sign-normalized largest remainder (ALC).
- Snowflake division: cast operands to `NUMBER(38,18)` and multiply before dividing (verified scale behavior, G-ALC-06).
- Quantities carry a unit: `{"value": "<decimal string>", "unit": "CREDIT|BYTE|GIB_MONTH|TOKEN|REQUEST|SECOND|..."}` (`contracts/common/quantity.schema.json`).
- Different currencies are never summed; a response containing several currencies returns one total per currency.
- The web app never computes financial totals; it formats server-provided decimal strings (`decimal.js` for formatting only).

## 6. Unknown, empty and partial

- Unknown value: `null` plus a sibling `<field>_reason` (enum in `contracts/common/unknown-reason.schema.json`: `NOT_SUPPORTED`, `NOT_ENABLED`, `DENIED`, `NOT_YET_AVAILABLE`, `OUT_OF_RETENTION`, `NO_PRICE`, `SUPPRESSED_PRIVACY`, `INSUFFICIENT_DATA`, `CAPABILITY_MISSING`, `TRIAL_ACCOUNT`). Zero means confirmed zero.
- Empty authorized result: HTTP 200, empty rows, coverage metadata. Partial data: HTTP 200 with `meta.coverage` and `meta.warnings`. Never HTTP 206 for business partiality.
- Maturity (`data_status`: `PROVISIONAL|FINAL|RECONCILED`), reconciliation result (`PENDING|MATCHED|WARNING|FAILED`) and period state (`OPEN|MONTH_STABLE|CLOSED|RESTATED`) are separate fields (ADR-003 + amendment).

## 7. HTTP API rules

- OpenAPI 3.1 is the single source; the FastAPI app is checked against it (contract tests), and the web client is generated from it (`openapi-typescript` + `openapi-fetch`).
- Tenant selection: browser and API clients send `X-Bridge-Tenant: <tenant_id>` on every tenant-scoped request; the server verifies active membership, echoes the header in the response, and the client rejects a response whose echo differs (tab-safety rule, G-API-13). Machine clients are bound to one tenant; the header must match. The web app URL carries the tenant slug (`/t/:tenantSlug/...`).
- Errors: RFC 9457 `application/problem+json` with extension members `code` (from `contracts/errors/problems.yaml`), `request_id`, `retryable`, optional `errors[]` (`{field, code, message}`) and `retry_after_ms`. Foreign or invisible objects return a non-enumerating 404.
- Writes: `POST` accepts `Idempotency-Key` (required on creates that have side effects); same key + different body → 409 `IDEMPOTENCY_KEY_REUSED`. Updates use `PATCH` with `If-Match: <revision etag>`; stale → **412** `PRECONDITION_FAILED` (CTL amendment).
- Reads: keyset pagination with sealed cursor tokens (API-003 spec); `limit` default 100, max 500; response `{data, next_cursor, meta}`. `meta` follows `packages/api_contracts/meta.schema.json` (publication_id, metric_version, source_as_of, data_status, coverage, price_basis, currency, warnings, request_id).
- Long work: `202 Accepted` + job resource with `Retry-After` (D-33 workers).
- Versioning: `/v1` path prefix; additive changes only within a version; deprecations carry `Deprecation` and `Sunset` headers and a changelog entry.
- Security headers, CSRF (double-submit token for cookie sessions), CORS allowlist and rate limits are defined once in `contracts/openapi/components/security.yaml`.

## 8. Events (transactional outbox)

Envelope (`contracts/common/event-envelope.schema.json`): `event_id` (UUIDv7), `type`, `schema_version`, `tenant_id` (null only for platform events), `occurred_at`, `producer` (service name + version), `aggregate_type`, `aggregate_id`, `aggregate_version` (monotonic per aggregate), `correlation_id`, `causation_id`, `privacy` (`NONE|CUSTOMER_METADATA|PERSONAL`), `payload`. Delivery is at-least-once, ordered per `(aggregate_type, aggregate_id)`; consumers deduplicate on `(consumer, event_id)` (CTL `platform.consumed_event`). Payloads carry IDs and versions, not personal data, unless the event type is classified `PERSONAL`.

## 9. State machines

Every lifecycle is declared in `contracts/state-machines/<name>.yaml`:

```yaml
machine: connection            # unique name
version: 1
owner_task: CON-006
entity: connection.connection  # table or aggregate
state_field: status
initial: DRAFT
terminal: [DELETED]
states:
  DRAFT: {description: "Configuration saved, not validated"}
  # ...
transitions:
  - {from: DRAFT, to: AWAITING_CUSTOMER_SETUP, event: script_generated, actors: [snowflake_admin], guards: [config_valid], effects: [emit:bridge.connection.connection.script_generated]}
invariants:
  - "REVOKED connections never receive new extraction leases"
```

Rules: every transition names its triggering `event`, allowed `actors` (capabilities or `system:<component>`), `guards` (named predicates defined in the owning task) and `effects` (events emitted, jobs enqueued). The linter rejects unreachable states, undeclared events and transitions out of terminal states; tests are generated for every declared and every undeclared (rejected) transition.

## 10. PostgreSQL DDL rules

- One or more files per schema in `contracts/postgres/` (`<schema>.sql` or `<schema>.<part>.sql`), each with a single owner (see `contracts/README.md`). Schemas: `identity, tenant, connection, sync, governance, allocation, finance, monitor, report, workflow, analytics, onboarding, commercial, privacy, support, audit, platform, ops`.
- Every tenant-owned table: `tenant_id uuid NOT NULL`, `id uuid NOT NULL` (UUIDv7), `created_at timestamptz NOT NULL DEFAULT now()`, `updated_at timestamptz NOT NULL DEFAULT now()`, `revision bigint NOT NULL DEFAULT 1`, `PRIMARY KEY (tenant_id, id)`, RLS `ENABLE` + `FORCE`, policy from the SEC RLS standard template, composite foreign keys including `tenant_id` (FK checks bypass RLS — G-SEC-10).
- Global tables (no tenant) are listed explicitly in the RLS standard with their access path.
- Status columns are `text` constrained by `CHECK (status IN (...))` generated from the state-machine file; no PostgreSQL enum types (migration friction).
- JSONB only for versioned, schema-validated documents (`*_json` suffix + `*_schema_version` column); never for queryable relational data.
- No analytical fact mirror (PRD §57): PostgreSQL stores IDs, statuses, bounded counts and references to Snowflake publications.

## 11. Snowflake object rules

- One central account per environment; database `BRIDGE`; schemas `RAW, CONTROL, CONFIG, SECURITY, STAGING, INTERMEDIATE, LEDGER, ALLOCATION, MARTS, SERVING, SERVING_JOBS, PUBLICATION, QUALITY, LINEAGE, SIMULATION, PY_OUTPUTS, OPS_META, OPS_INTERNAL`; internal cost facts in database `BRIDGE_INTERNAL_COST` with no customer-facing grants.
- Fact tables follow ADR-014 (revisioned, insert-only; `tenant_id`, `partition_key`, `revision_id` leading columns; clustering declared per dataset in `data/contracts/datasets.yaml`).
- Every Bridge session sets `TIMEZONE='UTC'`, `QUERY_TAG` per `data/contracts/query_tag.schema.json`, statement timeout per role; secondary roles are disabled for serving identities (D-02).
- Row access policies attach to base tables of serving datasets (G-DBT-06); readers never receive RAW, CONTROL, CONFIG or SECURITY grants.

## 12. Privacy classification

Every field in a data contract, event schema and log schema declares `x-privacy`: `PUBLIC`, `INTERNAL`, `CUSTOMER_METADATA` (object names, warehouse names), `PERSONAL` (user names, e-mails — pseudonymized per D-10), `SQL_TEXT` (sanitized per ADR-009), `SECRET` (never persisted outside Secrets Manager). Logs may contain only `PUBLIC`, `INTERNAL` and IDs.

## 13. Versioning and compatibility

- JSON Schema `$id`: `urn:bridge:schema:<area>:<name>:v<major>`; breaking change → new major file, old kept until all readers migrate.
- Source contracts, metric registry, detector registry, rule AST and report templates are versioned registries; data rows record the version that produced them.
- Migrations follow expand → migrate → contract (REL-101); a contract change and the code consuming it land in the same PR or behind a feature flag.

## 14. Tests every contract must ship with

Positive and negative examples (`examples/` next to the schema, or `x-examples` in OpenAPI), a round-trip test in the consuming language, and — for anything tenant-scoped — a foreign-tenant example that must be rejected.
