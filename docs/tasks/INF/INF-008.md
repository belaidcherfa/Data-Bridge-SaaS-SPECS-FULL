## Detailed implementation steps

### Micro-task 1

Select and verify central account region/edition for row policies; record actual account identifiers and administrative authorization.

### Micro-task 2

Create role ownership boundaries, warehouses with resource monitors/timeouts, schemas and central WIF service users; production and staging do not share readers.

### Micro-task 3

Apply twice and diff grants; prove API reader cannot alter policies, read RAW or create objects, and transformer cannot access customer accounts.

## Data model

Separate environment accounts; schemas SECURITY/CONFIG/RAW/STAGING/INTERMEDIATE/LEDGER/PY/MART/SERVING; service-role grant manifest.

## API / interfaces

Reviewed idempotent DDL runner authenticates with human SSO for initial trust, then central WIF; no persistent key.

## Security and tenant isolation

IAM roles are environment-specific. No broad iam:PassRole, wildcard data access or public database/cache/Dagster. Verify access with both allowed and denied principals.

For this task, test a foreign tenant identifier and an invalid or revoked scope at every input boundary it introduces. Internal infrastructure tasks instead prove environment/principal isolation and absence of public access. Test artifacts use synthetic tenant A/B data only.

## Idempotency / retries

Terraform plans are repeatable; apply exact reviewed plan with state locking. ECS retries use immutable image/task revisions; queue jobs use durable idempotency keys.
