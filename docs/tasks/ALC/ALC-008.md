## Detailed implementation steps

### Micro-task 1

Select one allocation book and reconciled charge version; validate required approvals and unresolved differences before issue.

### Micro-task 2

Apply largest-remainder minor-unit rounding with stable target tie-breaker; preserve signed totals and record rounding deltas.

### Micro-task 3

Test1.00 thirds=0.34/0.33/0.33, negative counterpart, duplicate issue and corrected closed charge; create linked restatement.

### Micro-task 4 — Prove and checkpoint

Run the validation below, record expected versus observed results and environment versions, update operational documentation, then checkpoint the task index with the exact next action. Do not mark DONE while a required live gate is unexecuted.

## Data model

Statement book/period/currency/version, lines, approvals, evidence and predecessor; internal transfers net zero.

## API / interfaces

Preview/approve/issue/restate APIs with revision and idempotency; report renderer consumes frozen statement.

## Security and tenant isolation

Rule editors can target only their delegated scope. Simulation/results/group trees/statement URLs enforce tenant and group-book permissions. Publishing access-relevant classification changes requires permission review.

For this task, test a foreign tenant identifier and an invalid or revoked scope at every input boundary it introduces. Internal infrastructure tasks instead prove environment/principal isolation and absence of public access. Test artifacts use synthetic tenant A/B data only.

## Idempotency / retries

Versioned rule/config snapshots and deterministic allocation keys make reruns identical. Approval uses optimistic revision and input publication hash; issued statements remain immutable.

## Failure scenarios

Mixed currencies/books; unsupported invoice scope; missing approval; stale ledger; duplicate financial transfer.
