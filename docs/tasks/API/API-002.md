## Detailed implementation steps

### Micro-task 1

Parse typed requests, enforce range/cardinality/limit rules and resolve authorization scope before SQL generation.

### Micro-task 2

Compile identifiers only from registry and bind literals; select principal-specific pool and set timeout/query tags.

### Micro-task 3

Inject SQL in filters/sort/metric IDs, omit tenant filters, change profile and cancel a slow query; verify rejection or safe scoped execution.

### Micro-task 4 — Prove and checkpoint

Run the validation below, record expected versus observed results and environment versions, update operational documentation, then checkpoint the task index with the exact next action. Do not mark DONE while a required live gate is unexecuted.

## Data model

Typed query AST from allowlisted metrics/dimensions, bound filter values and pinned publication.

## API / interfaces

POST /v1/analytics/query; convenience GET /v1/cost delegates to same planner.

## Security and tenant isolation

Validate current membership, entitlement and query dimensions before cache/query planning. Principal/profile comes from server mapping; cursors/jobs/explain references are tenant- and scope-bound.

For this task, test a foreign tenant identifier and an invalid or revoked scope at every input boundary it introduces. Internal infrastructure tasks instead prove environment/principal isolation and absence of public access. Test artifacts use synthetic tenant A/B data only.

## Idempotency / retries

Reads pin publication; POST job/export writes use request hash+idempotency key and durable outbox. Cursor replay is safe within expiry; cancellation and completion compare fencing/revision.

## Failure scenarios

Planner estimate wrong; pool leaks principal; result too large; stale scope; client disconnect leaves costly query.
