## Detailed implementation steps

### Micro-task 1

Provision encrypted Aurora writer/reader topology with backups/deletion protection; create restricted migration/runtime identities.

### Micro-task 2

Provision Redis TLS/auth controls and eviction policy suitable for disposable cache; keep durable state in PostgreSQL.

### Micro-task 3

Allocate connection budgets across max ECS replicas, Dagster and workers; failover Aurora and flush Redis during synthetic requests.

### Micro-task 4 — Prove and checkpoint

Run the validation below, record expected versus observed results and environment versions, update operational documentation, then checkpoint the task index with the exact next action. Do not mark DONE while a required live gate is unexecuted.

## Data model

Separate bridge_control/dagster_meta databases and users; per-component pool budget <=70% tested connection limit.

## API / interfaces

TLS endpoints and short-lived DB authentication or rotated app secret; no Snowflake secrets.

## Security and tenant isolation

IAM roles are environment-specific. No broad iam:PassRole, wildcard data access or public database/cache/Dagster. Verify access with both allowed and denied principals.

For this task, test a foreign tenant identifier and an invalid or revoked scope at every input boundary it introduces. Internal infrastructure tasks instead prove environment/principal isolation and absence of public access. Test artifacts use synthetic tenant A/B data only.

## Idempotency / retries

Terraform plans are repeatable; apply exact reviewed plan with state locking. ECS retries use immutable image/task revisions; queue jobs use durable idempotency keys.

## Failure scenarios
