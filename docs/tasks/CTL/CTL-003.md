## Data model

Invitation hashed token, expiry, intended tenant/role/scope; revision on all mutable definitions.

## API / interfaces

POST /v1/tenants; /invitations; PATCH /memberships/{id}; GET /teams; If-Match and Idempotency-Key.

## Security and tenant isolation

Apply SEC-004 policies to every new tenant table, validate composite FKs and object scopes in repositories. Logs and caches carry only safe scoped data.

For this task, test a foreign tenant identifier and an invalid or revoked scope at every input boundary it introduces. Internal infrastructure tasks instead prove environment/principal isolation and absence of public access. Test artifacts use synthetic tenant A/B data only.

## Idempotency / retries

Transactionally bind mutation, audit and outbox; unique idempotency keys and optimistic revisions prevent duplicate effects. Durable leases use fencing, not Redis locks.

## Failure scenarios

Concurrent role edits; invite forwarding; duplicate email; expired token; two owners removed concurrently.
