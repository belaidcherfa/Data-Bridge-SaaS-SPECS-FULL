# External tags, allocation, usage groups, showback and chargeback

Canonical domain contract. Owner: FinOps / Backend / Frontend. Implementation state: NOT_STARTED.


## External semantic ownership

Tag Studio is an external classification layer; it does not modify customer Snowflake tags in release one. Supported dimensions include business_unit, team, owner, cost_center, product, project, environment, application, customer, domain, workload, SLA and criticality, plus typed tenant-defined dimensions. Native tags are evidence inputs, not automatically privileged truth. Record value, source, confidence, valid_from/to, ruleset version and override provenance.

Rules use a typed bounded expression AST over approved resource/query/session/workload metadata. No arbitrary SQL/Python/eval. (amended 2026-09-28, D-16, G-ALC-02) The AST is disjunctive normal form (≤ 8 × 8 predicates, ≤ 1,000 values) compiled into versioned **predicate tables** (dimension, operator, value, priority, rule_version) that one generic set-based SQL model evaluates for all tenants; no per-tenant code generation. R1 operators: `eq`, `in`, `prefix`, `suffix`, `contains`, `is_null` and their negations; `regex` is R2 after cost testing. A NULL attribute makes every operator false except `is_null`. Subject levels resolve OVERRIDE > ACTIVITY (query, task run, Cortex call) > OBJECT > CONTAINER (schema → database → account) > inherited carrier (a query inherits its warehouse's assignment) > UNCLASSIFIED, priority compared within a level. User-name predicates accept only `eq`/`in` and are compiled to pseudonyms at publication (D-10). Explicit priority wins; overlapping equal-priority assignments of different values are conflicts that block publication unless an explicit resolution is approved; conflicts first seen in data arriving after publication never pick a winner — the subject goes to the UNASSIGNED leaf with status CONFLICT and a quality alert. Manual overrides are scoped, effective-dated and audited. Unmatched objects remain unclassified. Reclassification must not retroactively mutate closed statements.

Lifecycle: DRAFT → SIMULATING → REVIEWABLE → APPROVED → PUBLISHING → PUBLISHED; failures return to a recoverable state. Preview includes affected resources/charges, coverage before/after, conflicts, monetary movement, sample evidence and permission impact. A rule that changes access-relevant group membership requires authorization review before publication. PostgreSQL owns definitions/approvals; Snowflake owns applied tag/allocation facts and simulation results via immutable config versions. (amended 2026-09-28, D-04, C-05, G-ALC-07) Published versions are written by the config publisher; drafts go to `SIMULATION_INPUT`. A simulation is a dbt build (`allocation_sim` selector) run as a Dagster dbt job with an API job record; its window defaults to 90 days for cost and may extend to the 365-day query-level retention (D-11). A simulation pins its input publication, window and scope plus a fingerprint of the charges and revisions inside that window; approval is invalidated only by a revision inside the window, a dependency version change, a ruleset change or an age above 7 days — never by data appended after the window.

## Usage group sets

A set is an independent classification book, e.g. Teams, Products, Cost Centers or Environments. One charge may appear once in each set; totals from different sets must never be summed. Within a set, assignments are mutually exclusive or explicitly weighted and conserved. Hierarchies are acyclic with effective dates; moving a child preserves old published hierarchy versions. Unknown/unassigned is an explicit leaf, not an omitted row.

## Allocation contract

Input = selected charge publication + tag/group/rule versions + effective period. Output grain = charge_id × allocation_book/group_set × target × rule_version. (amended 2026-09-28, D-12, G-ALC-01) Because `fct_charge` is a billing bucket (one account-day charge covers every warehouse), the only allocation input is `int_alloc_unit`: each charge is split into QUERY units (per warehouse and classification key), IDLE and HOUR_RESIDUAL units per warehouse, RESOURCE units from storage/serverless bridges and WHOLE units for charges without a bridge, summing exactly to the charge at 12 decimals. The output grain becomes charge_id × book × policy_version × component_kind × target group × method, so statements can show "Warehouse compute / Idle". Fields include signed source/allocated amount, currency, weight, method, status, evidence, rounding adjustment and lineage. Methods: direct, fixed percentage, proportional, query-cost, measured usage, weighted, shared pool, residual and approved manual transfer.

Each charge is processed once per book. Rules declare exclusive scope, precedence and eligible cost components. Fixed weights must sum to one. Proportional denominator zero or missing data leaves UNALLOCATED unless an explicit fallback rule is part of the approved preview. Shared pools cannot reference themselves or form cycles. Idle policy is explicit: warehouse owner, proportional eligible consumers or platform cost center. Estimated query allocation is labelled as an allocation method, not direct observed billed cost. (amended 2026-09-28, D-15, G-ALC-10) Method algorithms, fallback chains and manual transfers are normative in [ALC backlog](../22-implementation-readiness/backlog/ALC.md) G-ALC-10: proportional idle is computed per (charge, warehouse, usage date) with unassigned consumers kept in the denominator; negative drivers go to UNALLOCATED (`NEGATIVE_DRIVER`); R1 shared pools are single-level (a pool-to-pool reference is rejected); at most one residual method per book; manual transfers are book-level ± lines with `charge_id` null that net to zero per book, period and currency. The **default book seeded at onboarding** (ALC-103, editable) is: warehouse compute by query cost; idle proportional to consumers → owner → UNALLOCATED; cloud services proportional to gross cloud-services credits (labelled query-cost share until `CREDITS_USED_CLOUD_SERVICES` is extracted); storage by database owner; serverless by owning object; transfer, replication, organization fees and rebates to a platform group; everything else, including unmapped services, UNALLOCATED ([ADR-015](../architecture/adr/ADR-015-financial-grain-maturity-attribution.md)).

Conservation per charge/book/currency:
`direct + rule_allocated + shared + unallocated = source_charge`.

Use exact decimals; allocate at internal precision. (amended 2026-09-28, G-ALC-05, U-20) Statement rounding is the **sign-normalized signed largest remainder** of FIN-106 (`round_statement_lines`), applied hierarchically (book total → targets → each target's lines) with a stable target-ID tie-breaker; the same function allocates at 1e-12 internally. The former "largest remainder on absolute amounts, then reapply sign" is withdrawn: for lines +1.005, −0.335, −0.335 (exact sum +0.335, rounded total 0.34) it produced +1.00 −0.34 −0.34 = 0.32. 1.00 split three ways still becomes 0.34/0.33/0.33 and -1.00 becomes -0.34/-0.33/-0.33; the mixed example now sums to 0.34. Manual internal transfers have equal/opposite entries and preserve total; they never alter the original Snowflake charge.

Under platform-idle policy: Finance84, Marketing56, Platform60. Both total200; alternative policies are separate versions, not additive results. ## Showback and chargeback

Showback is an authorized business portal over allocations: current spend, budget/forecast, change, top workloads, new spend, risks and opportunities. It does not transfer money. Chargeback selects one book, period, currency, pricing and allocation version, requires reconciliation/approval, and creates immutable statement lines and explanation links. It is an internal cost statement, not automatically a legally compliant sales invoice. Corrections follow FIN close/restatement rules. (amended 2026-09-28, G-ALC-12, G-FIN-11, G-RPT-05) Issuing a statement is maker-checker; issued statement artifacts belong to the RECORD retention class (max(400 days, contract), Object Lock GOVERNANCE) and their Snowflake lines are retained at least as long; a period can be issued only after it is MONTH_STABLE and closed, or under an explicitly approved exception. Showback may show provisional current periods; issued chargeback must state required final/reconciled coverage or an explicitly approved exception.

## Quality and UX

Quality view reports direct/rule/shared/unallocated shares on the FIN absolute-amount coverage basis, conflicts and unowned resources. Every count/amount opens the corresponding remediation filter. Group-limited users see only authorized allocations and an allowed share of shared costs; neither hidden groups nor hidden grand totals leak through percentages. (amended 2026-09-28, G-ALC-03, G-ALC-04) Team-restricted readers read only the **restricted projection** `srv_allocation_restricted` (tenant, book, target group, usage date, service category, component kind, method, allocated amount, data status, explain reference) — never source amounts, weights, numerators, denominators or pool totals, because with two consumers any weight/denominator pair reveals the sibling's exact amount. Pool and idle disclosure defaults to CONCEALED (DISCLOSED needs an Organization Admin acknowledgement). The API rejects share-of-total, coverage and unallocated `spend` for group-restricted profiles. Group-scope authorization is materialized by a security-owned job (ALC-101) from grants × the effective-dated published hierarchy into Snowflake entitlements checked by `CURRENT_ROLE()` (D-02); grants follow the published hierarchy instead of pinning versions. Simulation screens show data and rule versions and require rerun when either changes before approval.
