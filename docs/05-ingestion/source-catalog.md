# Snowflake source catalog and activation contracts

Verified against official documentation on 2026-09-23. **No live account schema or grants were tested.** ING-001 and CON-005 perform mandatory account-specific verification before activation. Names below are Snowflake source fields; tenant/batch/privacy columns are Bridge-generated and must never be queried as customer source columns.

## Common source activation gate

For every row: fetch the linked official definition; explicitly list only needed fields; record actual types/nullability from the live account; verify source-specific read grants using the organization/account role map; test a bounded interval; validate candidate-key uniqueness or declare aggregation/snapshot semantics; record retention and latency; run one WIF extraction and one replay fixture. Do not silently coerce undocumented data. Unknown optional fields are excluded until approved. Any documented view not available in that account remains capability-disabled, with financial top-line coverage supplied independently where possible.

`AU` means `SNOWFLAKE.ACCOUNT_USAGE`; `OU` means `SNOWFLAKE.ORGANIZATION_USAGE`. A source without an immutable unique row ID is loaded as a **complete scoped partition snapshot** and normalized at its documented grain. Aggregate truly identical dimensional rows within that snapshot, summing measures; do not collapse legitimate repeated amounts by row hash alone. Latest complete snapshot replaces the partition logically.

## Operational defaults versus vendor guarantees

For extension sources without a finalized per-account contract, do not schedule extraction. ING-001 must fill exact projection/grain and official latency/retention then prove them live. Start hourly sources with 24h overlap and daily sources with seven-day overlap, plus weekly anti-entropy over 30 days and open-month billing refresh. These are engineering safety defaults, not claims that a source cannot correct older data. Compare closed months to versioned billing references periodically and reopen through the controlled restatement workflow.

## Source-specific test matrix

Every activated source must pass: empty authorized window; missing grant; missing optional column; missing key; decimal/type edge; duplicate physical attempt; same key revised measure; complete partition with deleted old row where applicable; late data beyond ordinary overlap; source retention clamp; account rename; tenant-ID collision; replay of prior schema version. Financial sources add native-unit totals and an independent billing comparison. Snapshot sources prove that pre-enrollment history is shown as unavailable.
