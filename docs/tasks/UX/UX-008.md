## Security and tenant isolation

Frontend visibility is convenience only; API/database enforce permissions. Scope-dependent query keys and forms clear on tenant switch/logout. Autocomplete, totals and exported links follow the same access policy.

For this task, test a foreign tenant identifier and an invalid or revoked scope at every input boundary it introduces. Internal infrastructure tasks instead prove environment/principal isolation and absence of public access. Test artifacts use synthetic tenant A/B data only.

## Idempotency / retries

Read views pin dataset version and query state; mutation forms use idempotency keys and revisions. Prevent double-submit while preserving safe retry after network failure.

## Failure scenarios

## Testing and validation

**Deterministic oracle:** All page/state/persona cases have evidence; no foreign names/totals; numeric views agree; zero critical accessibility blockers.

**Local:** the FND validation dispatcher must expose `make validate-task TASK=UX-008 ENV=local`. Implement the fixture before the behavior. Exercise the stated failure cases and retry the identical input; compare outputs with the oracle. Use unit/contract tests and local PostgreSQL/Redis integration where relevant. UI tasks add Playwright state assertions and keyboard checks; data tasks add dbt/Arrow contract assertions.

**AWS / Snowflake:** `make validate-task TASK=UX-008 ENV=staging` runs only against the isolated staging environment with short-lived identities. Run Playwright against staging Cognito/API/Snowflake fixtures under owner, restricted viewer and foreign tenant users; verify numeric values, accessibility, responsive layout and all error states.

**Required test selection:** include the relevant unit, contract, integration, tenant-isolation, security, failure/recovery, E2E/UX, performance and financial levels.
