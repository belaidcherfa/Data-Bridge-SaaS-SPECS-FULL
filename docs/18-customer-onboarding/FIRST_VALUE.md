# First-customer first-value checklist

Store completed records in the approved private customer system. This public repository contains the template only. Customer success owns coordination; the customer's administrator and finance owner approve their respective evidence.

1. Record authorized organization/accounts, region, source/privacy policy, requested history and commercial plan. Verify the initial admin and finance owner.
2. Run organization WIF and account discovery, then install per-account WIF using reviewed scripts. Verify wrong-account and revoked-role tests. Record optional/required capability differences.
3. Present requested versus retained/authorized dates for every source. Label snapshot histories as beginning at enrollment. Obtain acceptance of explicit gaps before starting the agreed backfill.
4. Follow extraction, committed journal, accepted RAW and published coverage independently. Close gaps with bounded repair. Show steady-state catch-up after historical work.
5. Reconcile a complete period by currency/service/account against the strongest independent approved reference. Record exact signed delta/tolerance and maturity. Missing invoice evidence does not pass invoice reconciliation.
6. Invite one restricted team member and prove denied access to an unassigned account/team. Set ownership dimensions; simulate allocation; verify allocated plus unallocated equals eligible ledger total.
7. Configure one meaningful budget and dry-run one monitor. Verify one customer-authorized notification and secure report delivery. Explain forecast uncertainty and partial-data behavior.
8. Review a supported insight and evidence, or record that no candidate meets the threshold. If acting, freeze a baseline and assign an owner; do not claim savings before post-change verification.
9. Generate the appropriate executive/team report and prove its numbers match Explorer/Showback at the same publication. Confirm support contacts and safe installation/revoke/offboard documentation.
10. Record first-value acceptance, unresolved limitations, owner/next action and scheduled first-week review. Commercial payment evidence remains a separate launch gate.

| Acceptance field | Required value |
|---|---|
| Tenant/customer reference | Private internal identifier |
| Customer admin / finance approver | Verified private references |
| Connected and selected accounts | Exact count and identity references |
| History | Requested range, available ranges, accepted gaps per source |
| Financial evidence | Period, currency, ledger/reference versions, delta, tolerance and actual status |
| Ownership/allocation | Published ruleset/book versions, conservation and unallocated amount |
| Governance | Budget/monitor/report IDs and authorized delivery receipt |
| Insight/action | Evidence reviewed; action/baseline only if applicable |
| Access review | Restricted persona test and membership sign-off |
| Support | Contacts, escalation coverage, next review date |
| Decision | ACCEPTED / ACCEPTED_WITH_DISCLOSED_LIMITS / NOT_ACCEPTED, reason and date |

Failure examples: eight connections with seven published accounts is partial;365 requested query days with241 available is not365 complete; successful Snowpipe load with failed dbt is not ready;270 ledger versus271 invoice is not reconciled. Keep these distinctions visible in the customer record.
