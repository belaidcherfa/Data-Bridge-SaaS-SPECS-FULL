## Detailed implementation steps

### Micro-task 1

Run simulation over selected authorized scope and produce coverage/conflicts/moved-spend/sample explanations.

### Micro-task 2

Require a fresh simulation and approval before publication; changed source/rules invalidate approval, and scope-affecting changes require security review.

### Micro-task 3

Publish through config outbox and show pending/accepted state; test lost ack and rollback without changing closed periods.

### Micro-task 4 — Prove and checkpoint

Run the validation below, record expected versus observed results and environment versions, update operational documentation, then checkpoint the task index with the exact next action. Do not mark DONE while a required live gate is unexecuted.

## Data model

Simulation pins input publication/ruleset and stores results in Snowflake; approval references hash and reviewer.

## API / interfaces

POST /v1/rulesets/{id}/simulate; approve; publish; rollback to prior version.

## Security and tenant isolation

Rule editors can target only their delegated scope. Simulation/results/group trees/statement URLs enforce tenant and group-book permissions. Publishing access-relevant classification changes requires permission review.

For this task, test a foreign tenant identifier and an invalid or revoked scope at every input boundary it introduces. Internal infrastructure tasks instead prove environment/principal isolation and absence of public access. Test artifacts use synthetic tenant A/B data only.

## Idempotency / retries

Versioned rule/config snapshots and deterministic allocation keys make reruns identical. Approval uses optimistic revision and input publication hash; issued statements remain immutable.

## Failure scenarios

Dataset changes during review; simulation timeout; partial publication; unauthorized reviewer.

## Observability

Emit task/component, request/run/batch identifier, outcome, duration and a safe error class. Correlate tenant identifiers in protected logs, not unbounded public metric labels. Exclude credentials, full SQL and raw customer payloads. Record counts/checksums or configuration versions appropriate to this task; alert on repeated failures through the shared platform monitoring contract.
