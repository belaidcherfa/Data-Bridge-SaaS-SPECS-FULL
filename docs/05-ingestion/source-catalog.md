# Snowflake source catalog and activation contracts

Verified against official documentation on 2026-09-23. **No live account schema or grants were tested.** ING-001 and CON-005 perform mandatory account-specific verification before activation. Names below are Snowflake source fields; tenant/batch/privacy columns are Bridge-generated and must never be queried as customer source columns.

(amended 2026-09-28) The implementation-readiness review corrected this catalog; corrections are marked in place. The per-source activation contract — scope and database role, watermark mode with the exact predicate, steady window with FIRST/SETTLE pass delays, semantics and key, backfill chunk and retention clamp, anti-entropy, privacy and special rules — is normative in [ING backlog](../22-implementation-readiness/backlog/ING.md) §3.1, the money authority per service family in [FIN backlog](../22-implementation-readiness/backlog/FIN.md) §3.2, and the maturity horizons in [ADR-015](../architecture/adr/ADR-015-financial-grain-maturity-attribution.md). Scheduling columns below are superseded by the hourly account-cycle (D-07, D-08): per-source overlaps become pass schedules plus anti-entropy.

## Common source activation gate

For every row: fetch the linked official definition; explicitly list only needed fields; record actual types/nullability from the live account; verify source-specific read grants using the organization/account role map; test a bounded interval; validate candidate-key uniqueness or declare aggregation/snapshot semantics; record retention and latency; run one WIF extraction and one replay fixture. Do not silently coerce undocumented data. Unknown optional fields are excluded until approved. (amended 2026-09-28, G-ING-03) Parquet field names are lower-snake from the registry and pipes load with `MATCH_BY_COLUMN_NAME=CASE_INSENSITIVE` (refines PRD §30 `CASE_SENSITIVE`); a case-fold collision in a projection is rejected. Record the source's `retention_class` (D-26: FINANCIAL 400 days, QUERY_GRAIN 90 days of journal and RAW). Any documented view not available in that account remains capability-disabled, with financial top-line coverage supplied independently where possible.

`AU` means `SNOWFLAKE.ACCOUNT_USAGE`; `OU` means `SNOWFLAKE.ORGANIZATION_USAGE`. A source without an immutable unique row ID is loaded as a **complete scoped partition snapshot** and normalized at its documented grain. Aggregate truly identical dimensional rows within that snapshot, summing measures; do not collapse legitimate repeated amounts by row hash alone. Latest complete snapshot replaces the partition logically.

## Operational defaults versus vendor guarantees

For extension sources without a finalized per-account contract, do not schedule extraction. ING-001 must fill exact projection/grain and official latency/retention then prove them live. Start hourly sources with 24h overlap and daily sources with seven-day overlap, plus weekly anti-entropy over 30 days and open-month billing refresh. (amended 2026-09-28, G-ING-01, G-ING-07) Overlaps are implemented as FIRST/SETTLE passes per window; anti-entropy on event sources is additive only; complete-partition sources apply the suspect guard (0 rows or a > 50 % primary-measure drop needs confirmation ≥ 6 h later) and are never re-snapshotted within 7 days of the retention cutoff; billing months are re-extracted until month end + 5 days (MONTH_STABLE, D-13). These are engineering safety defaults, not claims that a source cannot correct older data. Compare closed months to versioned billing references periodically and reopen through the controlled restatement workflow.

## Source-specific test matrix

Every activated source must pass: empty authorized window; missing grant; missing optional column; missing key; decimal/type edge; duplicate physical attempt; same key revised measure; complete partition with deleted old row where applicable; late data beyond ordinary overlap; source retention clamp; account rename; tenant-ID collision; replay of prior schema version. (amended 2026-09-28) Add: query longer than 2 h (QUERY_HISTORY) and longer than 15 h (QUERY_ATTRIBUTION_HISTORY) captured exactly once; no float field in Arrow/Parquet for a NUMBER source (`arrow_number_to_decimal`); TIMESTAMP_LTZ loaded with logical types; silently empty read on a complete partition held as SUSPECT; per-account schema fingerprint during a behavior-change bundle rollout. Financial sources add native-unit totals and an independent billing comparison. Snapshot sources prove that pre-enrollment history is shown as unavailable.
