## Security and tenant isolation

Telemetry, recovery copies and cost attribution carry sensitive tenant metadata. Restrict operational roles by purpose; test customer roles cannot query internal cost/audit/recovery schemas.

For this task, test a foreign tenant identifier and an invalid or revoked scope at every input boundary it introduces. Internal infrastructure tasks instead prove environment/principal isolation and absence of public access. Test artifacts use synthetic tenant A/B data only.

## Idempotency / retries

Monitoring observations deduplicate by event/window; restore and replay use durable manifests and fencing. Reconcile external side effects before resuming recovered outboxes.

## Testing and validation

**Deterministic oracle:** One trace correlates request to batch; zero planted secrets in logs; high-cardinality fixture does not create per-query metric series.

**Local:** the FND validation dispatcher must expose `make validate-task TASK=OPS-001 ENV=local`. Implement the fixture before the behavior. Exercise the stated failure cases and retry the identical input; compare outputs with the oracle. Use unit/contract tests and local PostgreSQL/Redis integration where relevant. UI tasks add Playwright state assertions and keyboard checks; data tasks add dbt/Arrow contract assertions.

**AWS / Snowflake:** `make validate-task TASK=OPS-001 ENV=staging` runs only against the isolated staging environment with short-lived identities. Execute timed drills in isolated AWS/Snowflake staging, using synthetic tenants and approved cost ceilings; collect measured evidence rather than treating configuration as proof.

**Required test selection:** include the relevant unit, contract, integration, tenant-isolation, security, failure/recovery, E2E/UX, performance and financial levels. Record `NOT_APPLICABLE` with a concrete reason for any level that does not exercise this task. Never replace a specified live behavior with a mock and report it as passed.
