# AWS platform, networking and deployment foundation

Canonical domain contract. Owner: DevOps. Implementation state: NOT_STARTED.


## Environment and network decision

Create DEV, STAGING, PROD AWS accounts under a managed organization, plus a security/log archive account when organizational ownership allows. EU-west-1 is the initial regional default; central Snowflake should be co-located where feasible. Region/residency and service availability are provisioning gates. (amended 2026-09-28, D-23) R1 is a single EU deployment; additional regions are separate stacks from the same code and Terraform modules, with no cross-region tenant data movement ([ADR-016](../architecture/adr/ADR-016-customer-coverage-residency-reachability.md)). Central Snowflake uses separate accounts per environment (BRIDGE_DEV, BRIDGE_STAGING, BRIDGE_PROD; PRD §134's "databases" is the minimum). Use two AZs minimum, public ALB/NAT subnets, private application subnets and isolated data subnets. (amended 2026-09-28, D-28) Public subnets hold only NAT gateways; the ALB is **internal**. ECS tasks have no public IP; Aurora/Redis have no public endpoint. Security groups allow only ALB→API/web, approved services→data, and required egress.

CloudFront distributes the frontend and API origin paths; disable caching on authenticated API responses. WAF attaches to the supported edge/regional resource; it is not an independent network hop. (amended 2026-09-28, D-28, G-INF-10) The React SPA is served from **S3 with Origin Access Control** and `/api/*` reaches an **internal ALB through a CloudFront VPC origin** (VERIFIED capability; origin TLS name matching TO VERIFY LIVE); the ALB security group admits only the CloudFront origin-facing prefix list. This replaces the public ALB protected by a secret header and refines PRD §5 (no Fargate `frontend` service). Route53/ACM validate hostnames; certificates for CloudFront and the Cognito custom domain live in us-east-1. Keep Dagster internal behind authenticated operations access: (amended 2026-09-28, G-INF-11) operators reach the read-only Dagster webserver and database diagnostics through SSM Session Manager port-forwarding via an on-demand `ops-bastion` task under an MFA-backed Identity Center permission set.

Use S3 gateway endpoints and appropriate private endpoints for ECR, logs, Secrets Manager, SQS and STS where supported. Controlled NAT egress reaches customer Snowflake endpoints, including non-AWS customer accounts; record cross-cloud transfer/privacy implications. PrivateLink is an optional validated capability, never an assumption for Standard/trial customers. (amended 2026-09-28, D-09, G-INF-09, C-13) NAT Elastic IPs are allocated once per environment with `prevent_destroy`, published to `infra/environments/<env>.egress.json`, SSM and `GET /v1/platform/egress-ips`, and changed only after 90 days of dual publication; the S3 gateway endpoint policy allows `s3:GetObject` broadly (ECR layers, Snowflake stage hosts from `SYSTEM$ALLOWLIST` for large result downloads) and restricts writes and deletes to Bridge accounts; DNS Firewall blocks managed threat lists VPC-wide; extractor destinations are validated in code with security-group egress 443 only; PrivateLink-only customer accounts are R2 (INF-106, CON-103). The interface-endpoint plan is 9 endpoints, 2 AZ in production, 1 AZ in staging, none in development.

## Terraform and runtime

Separate state per environment and foundational/application stack. Encrypted versioned S3 backend, provider-supported state locking, least-privilege apply roles, reviewed plans and drift detection. Bootstrap state resources with a small auditable root stack, then import them; never delete state to fix a lock. State can contain secrets and is access-controlled. Account/region guards refuse an unexpected destination.

Fargate services: frontend, API, connector tasks, Dagster web/daemon/code locations/run workers, intelligence, monitor and report workers. (amended 2026-09-28, D-07, D-22, D-28, D-33) The service set is: API/BFF; **query broker** (separate task role, the only principal with `sts:AssumeRole` on tenant serving roles, reached from the API by SigV4 through VPC Lattice — TO VERIFY LIVE — with Service Connect plus a security-group restriction as fallback; no private CA in R1); **extraction launcher** (the only principal with `ecs:RunTask` on the extractor task definition and `iam:PassRole` on `role/bridge-<env>-conn-*`, `iam:PassedToService=ecs-tasks.amazonaws.com`) and per-account-cycle **extractor tasks** whose default task role has no permissions; internal **sync-api**; ingestion/acceptance service; Dagster web (read-only), single daemon and code locations; **analysis-worker** and **render worker** (D-33; no Dagster report lane); intelligence, monitor and notification workers; the **identity provisioner** (INF-103); the config publisher; the ops API. There is no frontend service. Different task roles and resource limits; ECR digest images; non-root/read-only filesystems where compatible; bounded ephemeral storage. Daemon is single-active with recovery; API spans AZs. Task execution role pulls images/logs/secrets; task role authorizes application AWS calls. (amended 2026-09-28, G-INF-02, U-02, C-11) Runtime IAM roles are created only by the **INF-103 identity provisioner**, driven by outbox events: names `bridge-<env>-conn-<uuid32>` (per connection) and `bridge-<env>-srv-<uuid32>` (per tenant serving identity, no permission policies), no IAM path, a mandatory permissions boundary per kind enforced by the provisioner's own policy and an SCP backstop; the metric `iam_roles_used_ratio` alarms at 70 % and blocks admission at 80 % of the IAM role quota (default 1,000; adjustable to 10,000 since 2026-05, VERIFIED). [ECS IAM distinction](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/task_execution_IAM_role.html).

Aurora PostgreSQL uses multi-AZ failover, encrypted storage, backups and deletion protection. Initially use bounded application pools directly; evaluate RDS Proxy only after transaction-context/pinning tests, since RLS correctness takes precedence over multiplexing. [RDS Proxy pinning](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/rds-proxy-pinning.html).

ElastiCache Redis uses TLS, at-rest encryption, auth/ACL controls and private access; eviction/loss must be safe. S3 landing, reports, audit and Terraform state use separate policies, KMS keys and retention purposes. SQS queues have DLQs, bounded redrive and visibility extension. SNS provides Snowpipe fanout where required; application consumers do not poll Snowflake-managed queues.

## Capacity and observability defaults

Start with explicit small nonzero service minima in staging/prod and a documented budget. (amended 2026-09-28, G-INF-06, D-32) INF-105 (phase P0) creates AWS budgets per account, cost anomaly monitors, cost-allocation tags, a CUR 2.0 Parquet export for OPS-009, policy checks on every Terraform plan for the quantified cost traps (interface endpoints × AZ × environment, AWS Config recording of per-task ENIs at D-07 scale — exclude `AWS::EC2::NetworkInterface` —, Flow Logs to CloudWatch, SSE-KMS without bucket keys, private CA) and off-hours scale-to-zero in development; the baseline estimate is ≈ USD 2,000–3,650/month of AWS before customer scale ([INF backlog](../22-implementation-readiness/backlog/INF.md) G-INF-06). (amended 2026-09-28, G-INF-01, U-03, D-32) INF-101 provisions the single non-production **Snowflake test estate** — test organization T-A (organization account, Enterprise accounts on AWS eu-west-1 and on a second cloud, an idle discovered account) and T-B (Standard standalone account with colliding names), a continuous deterministic workload generator and canaries, tenant zero — capped at 150 credits/month by resource monitors, inside a 500 credits/month ceiling for all non-production Snowflake use. Do not invent CPU/RAM counts as proven sizing: choose initial values in task definitions, then benchmark the SLO matrix. Set statement, request and job timeouts; enforce per-tenant concurrency and account admission. Tag AWS resources by environment/component/cost_owner; per-job tenant usage is recorded separately to avoid cardinality explosion in infrastructure tags.
