## Data model

Step state/config revision/evidence references; analytical progress read from existing health APIs.

## API / interfaces

GET onboarding state; idempotent start/resume/pause commands delegate existing connection/sync interfaces.

## Security and tenant isolation

Customer authorization and selected accounts govern collection. Invitations and ownership assignments are tenant scoped; setup scripts contain identities and grants but no persistent Snowflake secrets.

For this task, test a foreign tenant identifier and an invalid or revoked scope at every input boundary it introduces. Internal infrastructure tasks instead prove environment/principal isolation and absence of public access. Test artifacts use synthetic tenant A/B data only.

## Idempotency / retries

Every step is keyed by tenant/configuration revision; repeated starts reuse active work and accepted batches. Reconnection preserves durable account IDs and data lineage.

## Failure scenarios

Browser loss; duplicate click; source revoked; no organization permission; unsupported history.

## Observability

Emit task/component, request/run/batch identifier, outcome, duration and a safe error class. Correlate tenant identifiers in protected logs, not unbounded public metric labels. Exclude credentials, full SQL and raw customer payloads. Record counts/checksums or configuration versions appropriate to this task; alert on repeated failures through the shared platform monitoring contract.
