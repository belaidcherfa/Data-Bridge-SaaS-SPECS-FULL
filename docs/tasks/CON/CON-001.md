## Detailed implementation steps

### Micro-task 1

Validate customer account identifier and expected tenant ownership; derive internal role name from UUIDs, never free-text SQL identifiers.

### Micro-task 2

Provision least-privilege task identity with assigned S3 prefix, approved task definition and no role-chaining permission to another customer.

### Micro-task 3

Attempt to change tenant/account/role ARN after creation and ensure a new reviewed connection revision is required.

### Micro-task 4 — Prove and checkpoint

Run the validation below, record expected versus observed results and environment versions, update operational documentation, then checkpoint the task index with the exact next action. Do not mark DONE while a required live gate is unexecuted.

## Data model

Connection record and IAM role binding unique by environment/tenant/account; no credential fields.

## API / interfaces

POST /v1/connections returns connection_id, setup state and registered identity; server resolves all launch parameters.

## Security and tenant isolation

Only authorized Snowflake/organization admins manage connections. Resolve connection IDs server-side into allowlisted role/account targets; no arbitrary ARN, hostname, SQL or privilege from a request.

For this task, test a foreign tenant identifier and an invalid or revoked scope at every input boundary it introduces. Internal infrastructure tasks instead prove environment/principal isolation and absence of public access. Test artifacts use synthetic tenant A/B data only.

## Idempotency / retries

Connection validation is idempotent by connection revision and probe version. Discovery upserts stable identities; grant scripts converge without replacing users or dropping unrelated grants.

## Failure scenarios

IAM quota; duplicate enrollment; account identifier spoofing; unauthorized PassRole; partial provisioning.
