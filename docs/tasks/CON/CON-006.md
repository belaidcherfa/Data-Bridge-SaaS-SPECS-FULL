## Data model

Connection revision/state transition log; setup/probe/capability evidence references.

## API / interfaces

POST /pause /resume /revoke with revision and idempotency key; no immediate data deletion on pause.

## Security and tenant isolation

Only authorized Snowflake/organization admins manage connections. Resolve connection IDs server-side into allowlisted role/account targets; no arbitrary ARN, hostname, SQL or privilege from a request.

For this task, test a foreign tenant identifier and an invalid or revoked scope at every input boundary it introduces. Internal infrastructure tasks instead prove environment/principal isolation and absence of public access. Test artifacts use synthetic tenant A/B data only.

## Idempotency / retries

Connection validation is idempotent by connection revision and probe version. Discovery upserts stable identities; grant scripts converge without replacing users or dropping unrelated grants.

## Failure scenarios

Browser closes during validation; stale setup script; revoke races task start; user loses admin role.

## Observability

Emit task/component, request/run/batch identifier, outcome, duration and a safe error class. Correlate tenant identifiers in protected logs, not unbounded public metric labels. Exclude credentials, full SQL and raw customer payloads. Record counts/checksums or configuration versions appropriate to this task; alert on repeated failures through the shared platform monitoring contract.

| UX requirement | Behavior |
|---|---|
| Persona | Snowflake administrator |
| Goal | guide a customer to a validated connection and safe lifecycle controls. |

| Acceptance criteria | READY requires successful identity and required-source probes; revoked connection launches no new task; customer understands historical gaps and next sync step. |
